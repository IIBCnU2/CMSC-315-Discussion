# Unit 7 Discussion: Sorting Algorithms

## Overview

This assignment compares Bubble Sort and Merge Sort.

## Learning Objectives

- Implement Bubble Sort
- Implement Merge Sort
- Understand divide-and-conquer
- Compare algorithm efficiency

## Requirements

1. Test Bubble Sort and Merge Sort.
2. Use multiple datasets.
3. Demonstrate edge cases.
4. Analyze performance.
5. Create a real-world sorting example.

## Discussion Board Reflection

After completing the programming assignment, add this reflection to your initial discussion post in LEO.

Your reflection should be approximately 150–200 words and address the following questions:

This assignment helped me understand the differences between sorting algorithms and why some are better for certain situations. Before this, I mostly focused on getting the list sorted, but now I see that how an algorithm sorts can make a big difference when the amount of data gets larger. One challenge I had was keeping track of the strengths and weaknesses of each algorithm. At first, some of them seemed very similar. I got past that by comparing their runtimes and looking at examples of when each one would be useful. Running the code and seeing the results helped everything make more sense. Bubble Sort and Insertion Sort are easy to understand, but they slow down a lot with large datasets. Insertion Sort can still be useful when the data is already mostly sorted. Merge Sort is much faster for larger lists and keeps equal items in the same order, but it uses extra memory. Quick Sort is also very fast most of the time and is commonly used, but its performance can drop if a poor pivot is chosen. Overall, there is no single best sorting algorithm. The right choice depends on the size of the data, available memory, and whether stability is important.
